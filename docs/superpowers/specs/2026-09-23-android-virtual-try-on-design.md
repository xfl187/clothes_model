# Android 私人 AI 换装应用设计

日期：2026-09-23  
状态：V1 与 V1.1 已通过完整产品规格审查；本机优先素材库增量规格已通过审查
范围：V1 产品及 V1.1 分层穿搭、Android 客户端、固定云端业务服务、AutoDL ComfyUI 计算节点和 Web 管理页

## 1. 目标与成功标准

本项目是一款个人长期使用的 Android 换装应用。用户从人物素材库选择自己的照片，从衣物素材库选择衣物照片，系统尽量保持人物身份、姿势、体型和背景不变，仅替换目标衣物区域。

首版成功标准：

- 人物和衣物导入一次后保存在 Android 私有素材库中，可离线浏览、选择并重复使用；生成时按需同步到固定后端。
- 支持上衣、下装和连衣裙，每个任务选择一件衣物。
- 支持大模型直连与 ComfyUI 两类生成后端，并允许设置默认后端及单任务覆盖。
- AutoDL 离线时，ComfyUI 任务能持久排队、恢复执行并允许取消。
- 每张人物照片可生成 1–4 个候选，默认 1 个。
- 自动检查输入质量；检测失败只提示风险，不默认阻止提交。
- 自动遮罩不理想时，用户可手动补画或擦除后重新生成。
- 收藏的素材和结果长期保存，其他生成文件按策略自动清理。
- 更换 AutoDL 地址、模型连接或 ComfyUI 工作流时不需要重新发布 Android App。

首版为单用户、Android-only 产品，不包含公开注册、商业化或应用商店运营能力。

## 2. 范围边界

### 2.1 首版包含

- Kotlin 与 Jetpack Compose 原生 Android App。
- 人物素材库、衣物素材库、任务历史和收藏。
- 上衣、下装、连衣裙三类衣物。
- 商品图、平铺图、悬挂实拍图。
- 对“他人穿着图”进行实验性的衣物提取；遮挡区域允许模型推测，不承诺商品级还原。
- 精准换装模式。
- 一种可配置的大模型适配器。
- 一个可更换地址的 AutoDL ComfyUI 计算节点。
- 可取消、可恢复的持久任务队列。
- 工作流版本、验证、启用和回滚。
- Web 管理页。
- 独立的 App 令牌和管理员令牌。

### 2.2 首版不包含

- 创意写真生成；仅保留入口、模式枚举和接口扩展点。
- 多张人物照片一次提交。
- 多角度人物参考和跨视角联合一致性。
- 多件衣物组成整套穿搭。该能力作为 V1.1 独立产品模式交付，不进入 V1 必交范围。
- 多用户、iOS 或面向用户的 Web 换装客户端。
- 多个 ComfyUI 节点的负载均衡。
- ComfyUI 不可用时静默切换到大模型。
- 系统推送通知。

### 2.3 V1.1 分层穿搭范围

V1.1 在 V1 单件精准换装稳定运行的基础上增加“分层穿搭”独立入口，不替换原有精准换装：

- 一次会话选择一张原始人物图，逐件添加衣物并确认每一步结果。
- 首期提供 `inner_top`（内搭）、`outerwear`（外套）、`lower_body`（下装）和 `dress`（连衣裙）四种系统层级类型。
- 分体路线支持内搭、下装和外套；连衣裙路线支持连衣裙和外套。连衣裙与内搭、下装互斥，切换路线时创建新分支。
- 每一步可生成 1–4 个候选。默认选择一个候选继续，其他候选可由用户主动另存为独立分支。
- 支持回退、替换或移除已有层。修改中间层后，后续衣物保留为“待重新应用”，由用户逐层选择重新生成、更换或移除，不自动产生任务或费用。
- 已确认的人物、背景和衣物采用“尽量保持”的生成目标；不承诺像素级锁定。明显漂移时允许接受、重试、修正遮罩或更换 Provider。
- V1.1 不开放完全无语义的用户自定义衣物类型。未来自定义名称必须映射到系统认识的身体区域、层级关系和生成策略。

## 3. 总体架构

系统由三个部署边界组成：

```text
Android App
    │ HTTPS + App Token
    ▼
固定云服务器：模块化单体业务后端
    ├── 认证与令牌
    ├── 素材和文件
    ├── 任务队列与调度
    ├── 大模型适配器
    ├── ComfyUI 适配器
    ├── 清理与备份
    └── Web 管理页
            │ 认证连接或私有通道
            ▼
AutoDL：ComfyUI 计算节点
    ├── 模型
    ├── 自定义节点
    └── GPU 推理
```

固定云服务器是唯一业务入口和长期数据来源。AutoDL 只承担 ComfyUI 推理，允许关机和更换实例。Android 不直接访问大模型厂商或 ComfyUI。

### 3.1 模块化单体

首版后端使用一个部署单元，内部保持清晰模块边界：

- `Auth`：App/管理员令牌校验及权限范围。
- `Assets`：人物、衣物、结果和中间文件。
- `Jobs`：任务、子任务、状态机、取消和重试。
- `Outfits`：分层穿搭会话、不可变版本、分支、衣物层和待重新应用状态。
- `Providers`：统一生成接口及具体适配器。
- `Workflows`：ComfyUI 工作流、绑定清单和版本。
- `Admin`：配置、连接测试、任务诊断和存储状态。
- `Cleanup`：到期文件、AutoDL 临时副本和孤立文件清理。

首版不要求 Redis、Celery 或微服务。任务状态持久化在数据库中，进程内后台调度器领取任务。模块接口需允许未来把执行器拆成独立 Worker。

## 4. Android 产品流程

### 4.1 首次配置

用户填写固定云服务器地址和 App 令牌。App 验证服务器身份和令牌后保存连接配置。大模型密钥、ComfyUI 地址和工作流配置不进入 Android。

App Token 被轮换、撤销或因其他原因失效时，Android 保留服务器地址并进入“需要重新认证”状态，停止继续发送需要认证的请求，并提示用户输入新令牌。本机素材库和未提交草稿仍可浏览与编辑；上传、生成及服务端历史同步暂停。服务端已有任务不因客户端令牌失效而取消；重新认证成功后，App 同步任务、逻辑素材记录及上传副本状态。

### 4.2 首页

- 主入口为“精准换装”。
- V1.1 增加与“精准换装”并列的“分层穿搭”入口。
- 展示“创意写真”占位入口，明确标注未开放。
- 展示最近任务和状态。
- 提供人物库、衣物库和全部历史入口。

### 4.3 人物素材库

- 从手机相册导入。
- 导入时把完整原图复制到 Android 私有存储，并立即创建可重复选择的本机素材；相册 URI 不作为长期来源。
- 后端不可用时仍可浏览、筛选、选择本机素材并保存换装草稿。
- 首版创建任务时单选；选择组件和接口使用列表结构，为未来多选留出空间。
- 显示质量检测提示：多人、遮挡、分辨率过低或目标区域不完整。尚未上传并经过后端检测的本机素材显示“尚未检测”，不得伪造检测结果。
- 半身照不视为失败。校验依据衣物类别判断目标区域是否可见：上衣关注上半身和袖部，下装关注腰部及下装区域，连衣裙关注躯干和主要裙摆区域。

### 4.4 衣物素材库

- 保存衣物类别：`upper_body`、`lower_body`、`dress`。
- 保存来源：商品图、平铺/悬挂实拍图、他人穿着图。
- 自动分类结果允许人工修正。
- 他人穿着图标记为实验性来源。系统尝试分割衣物和去除人物背景；不可见纹理、版型和 Logo 可能由模型推测。

人物和衣物采用一致的本机优先规则：导入成功即进入 Android 私有素材库，完整本机副本、预览、类别和来源元数据由设备持久保存。素材在首次用于生成时才按需上传；上传失败或网络中断时保留本机素材及草稿，并允许重试或取消，不要求重新进入相册选择。取消上传后，或上传任务在服务端确认不再继续后，服务端清理未完成的临时文件。App 被关闭后再次打开时，应能恢复本机素材、草稿和未完成同步状态。

删除无引用的本机素材只删除设备副本，不静默删除后端副本或改写任务历史。仍被未提交草稿、未删除穿搭会话、分支、确认版本或待重新应用配置引用的本机素材不得直接删除；系统须列出引用，并要求先移除、替换或删除相应引用。App 卸载或清除数据会移除设备素材；V1 不提供云备份或跨设备同步。

升级到本机优先版本后，Android 在首次认证连接时自动把当前所有者范围内仍可访问的服务端人物和衣物原图下载到私有素材库。每项只有在完整文件持久化并校验成功后，才向后端确认本机副本可靠并允许该服务端输入副本进入清理计时。迁移中断时保留已完成项并续传剩余项；设备空间不足时暂停且不得删除未确认项的服务端原图；认证范围改变时立即停止，不能在另一所有者范围下继续。

### 4.5 创建任务

1. 选择一张人物图。
2. 选择一件衣物。
3. 使用默认后端，或为本任务覆盖为大模型/ComfyUI。
4. 选择每张人物图生成 1–4 个候选，默认 1 个。
5. 显示后端能力及输入质量警告。
6. 提交时上传尚无可用后端副本的所选素材，完成后以逻辑素材 ID 创建任务并进入任务详情；离开页面不影响执行。

后端不可用或令牌失效时不创建任务，保留本机选择和草稿并提示连接或重新认证。网络恢复后从上传步骤继续。后端对输入给出阻断性无效结果时不创建任务，保留本机素材和草稿供更换或修正；现有的非阻断质量警告仍允许用户继续。

App 只显示当前后端实际支持的选项。能力不足时隐藏或禁用对应控件，并解释原因。

ComfyUI 节点临时离线时仍允许提交，任务进入 `waiting_provider`。如果所选后端没有活动配置、锁定工作流与后端能力不兼容、配置校验失败，或存在其他已知且无法通过等待自行恢复的配置错误，则阻止提交并说明需要管理员处理，不创建注定无法执行的任务。

### 4.6 任务与结果

任务状态包括：

- `queued`：已入队。
- `waiting_provider`：等待 ComfyUI 等生成节点恢复。
- `preparing`：上传或预处理。
- `running`：生成中。
- `needs_attention`：外部执行状态无法确认，已停止自动推进，等待重新查询或人工决定。
- `succeeded`：全部成功。
- `partially_succeeded`：部分候选成功。
- `failed`：不可恢复失败或重试耗尽。
- `cancelled`：已取消。

结果页支持原图对比、下载、收藏、删除和按原参数重新生成。同参数重试在原主任务下创建新的子任务，保留旧尝试记录，并依据当前各子任务结果重新计算主任务状态。遮罩不正确时，用户可进入画笔界面补充或擦除遮罩；由于输入已改变，重新生成时创建与原任务关联的新主任务，原任务及其结果保持不变。若原 Provider 不支持手动遮罩，用户可为修正任务选择另一个支持该能力且与衣物类别兼容的 Provider，并明确看到后端已经改变；没有兼容 Provider 时说明当前无法执行遮罩修正。首版验收环境至少配置一个支持手动遮罩的 Provider。

### 4.7 V1.1 分层穿搭

1. 用户从首页进入“分层穿搭”，选择一张原始人物图并创建穿搭会话。
2. 工作台显示当前确认图片、已应用衣物层和可添加的系统层级类型。
3. 用户选择衣物、Provider 和候选数，创建关联的单衣物 `TryOnJob`。
4. 任务成功后，用户必须选择一个候选设为当前结果，系统才提交新的穿搭版本。未选候选继续保留，并可“从这里创建新搭配”。
5. 用户可继续添加衣物。首期不强迫按固定操作顺序添加，例如允许“内搭 → 外套 → 下装”；系统层级类型负责遮罩、兼容和冲突判断，生成步骤顺序单独记录。
6. 层级管理支持替换、移除、回退和从当前版本创建分支。旧版本和旧分支不被覆盖。
7. 修改中间层时，系统从该层应用前的最近确认版本重新生成；原后续衣物保存为待重新应用配置。每个后续步骤由用户选择重新应用原衣物、更换衣物或移除。
8. “重新应用”使用原衣物素材和参数在新基底上再次生成，不复制旧结果中的像素，因而会产生新的任务和可能的费用。
9. 分支可命名、收藏或设为当前主线。任务技术状态继续在复用的任务详情页展示。

切换分体路线与连衣裙路线时，系统从原始人物图创建新分支并移除与目标路线互斥的层：切换到连衣裙路线时移除内搭和下装，切换到分体路线时移除连衣裙。两条路线都兼容的外套不复制旧合成像素，而是作为 `pending_reapply` 配置保留；用户确认新路线的基础衣物后，再明确选择重新应用、更换或移除外套。路线切换和保留配置本身不得自动创建生成任务或产生费用，原分支保持不变。

重新应用衣物时，系统优先预填原任务使用的 Provider 和参数，但重新应用始终是一个新任务。若原 Provider、模型或工作流已不可用或不再兼容当前层级，系统不得静默切换，也不得创建注定失败的任务；用户可明确选择新的兼容 Provider，并在提交前看到 Provider 或参数发生了变化。新任务记录实际使用的配置版本，旧任务记录保持不变。没有兼容 Provider 时，待重新应用状态继续保留，并说明当前无法执行。

## 5. 任务模型与执行

任务采用“主任务 + 子任务”结构：

```text
TryOnJob
├── person_asset_ids[]
├── garment_asset_id
├── provider_selection
├── mode
├── generation_options
└── JobItem[]
    ├── person_asset_id
    ├── candidate_index
    ├── state
    ├── attempts
    └── outputs[]
```

首版 `person_asset_ids` 只含一个元素，但结构直接支持未来多人物批量生成。每个“人物 × 候选”对应一个子任务，以便单独重试、取消和表达部分成功。

### 5.1 数据流

1. Android 从私有本机素材库选择人物或衣物；若所选内容没有可用后端输入副本，则先按内容哈希上传并关联其逻辑素材记录。
2. 创建任务时提交逻辑素材 ID 和生成参数；仍有可用后端输入副本时不重复上传。
3. 后端持久化主任务及子任务，同时锁定本次任务实际使用的 Provider 配置版本和 ComfyUI 工作流版本，然后立即响应。
4. 调度器依据任务选择对应 Provider。
5. 大模型任务由适配器转换为厂商请求。
6. ComfyUI 任务先检查节点健康状态；离线则进入 `waiting_provider`。
7. 节点在线时，后端把任务所需输入上传到 ComfyUI，填充工作流并提交队列。
8. 后端跟踪生成状态，把结果取回固定服务器并清理 AutoDL 临时文件。
9. Android 通过轮询查看状态；推送通知不在首版范围内。

### 5.2 幂等与恢复

- 每个子任务具有全局唯一 ID，并作为外部调用的幂等键。
- 重复的 Android 创建请求不得重复扣费或生成。
- 服务重启后恢复 `queued` 和 `waiting_provider` 状态。
- `waiting_provider` 不自动过期。任务持续等待到兼容节点恢复或用户取消，并向用户显示等待原因和已经等待的时长。
- 对重启时的 `running` 任务，先查询外部状态；无法确认时不得盲目重复执行，任务进入 `needs_attention`。
- `needs_attention` 任务停止自动执行。用户或管理员可再次查询外部状态；仍无法确认时，可明确选择以新子任务重试，或结束为失败。系统不得把人工重试冒充为原外部执行的继续。
- 任务创建时锁定会影响生成语义的 Provider 配置版本、模型参数和工作流版本。任务在 `queued`、`waiting_provider` 或 `needs_attention` 中等待期间，即使管理员切换默认后端、模型连接或活动工作流，也不得静默改变这些锁定内容。
- AutoDL 节点地址属于可替换的物理计算基础设施，不随任务锁定。等待中的任务可迁移到新的 AutoDL 节点，但新节点必须通过锁定工作流的模型、自定义节点和输入输出兼容性检查；兼容性不通过时任务不得提交到新节点。
- 锁定的配置版本已不可用时，不自动改用最新配置；任务进入 `needs_attention`，由用户或管理员决定恢复原配置、按新配置创建重试，或结束为失败。
- 网络和临时限流使用指数退避与最大尝试次数；配置错误不自动重试。
- 失败子任务按原参数重试时，不覆盖或复用旧子任务记录，而是在同一主任务下创建新的子任务并记录其来源。旧失败尝试继续保留，用于解释执行历史、错误和可能产生的费用。
- 新子任务完成后，系统重新计算主任务的汇总状态；只要仍有最终失败且未被成功重试替代的候选，主任务保持 `partially_succeeded` 或 `failed`。

### 5.3 取消

- 用户可取消整个主任务，也可单独取消尚未完成的候选子任务。单独取消一个候选不影响其他候选继续执行。
- `queued`/`waiting_provider`：立即取消选定的未完成子任务。
- `preparing`：停止选定子任务的后续步骤并清理临时文件。
- `running`：向 Provider 发出尽力中断请求。无法中断时允许远端完成，但丢弃被取消子任务的迟到结果并清理文件。
- 取消整个主任务时，对所有未完成子任务执行上述取消规则。若取消后已有至少一个成功结果，保留成功结果并将主任务汇总为 `partially_succeeded`；若没有任何成功结果，则主任务为 `cancelled`。
- 终态任务不再“取消”。用户可删除其中的图片，但任务参数、状态和执行谱系作为历史元数据继续保留，并显示已删除素材的占位状态。

取消标记在执行每个阶段前检查，避免竞态导致取消后继续提交下一步。

### 5.4 V1.1 穿搭会话与版本

分层穿搭使用“会话 + 不可变版本树 + 单件生成任务”结构：

```text
OutfitSession
├── original_person_asset_id
├── active_revision_id
├── layer_definition_set_version
└── OutfitRevision[]
    ├── parent_revision_id
    ├── base_image_asset_id
    ├── selected_output_asset_id
    ├── source_job_id
    └── OutfitLayer[]
        ├── garment_asset_id
        ├── layer_role
        ├── layer_definition_version
        ├── sort_order
        ├── application_state
        ├── applied_by_job_id
        └── mask_and_generation_refs
```

- `OutfitRevision` 是不可变快照。确认候选、替换衣物、移除衣物或另存分支均创建新版本，不覆盖旧版本。
- `OutfitLayer.layer_role` 在数据库中使用可扩展字符串，而不是四个固定字段。API 按当前层级定义版本验证允许值。
- `OutfitSession.layer_definition_set_version` 在创建会话时锁定；旧会话和旧版本始终按锁定定义解释，不因系统增加或修改层级类型而改变语义。
- `OutfitLayer.application_state` 至少包含 `applied` 和 `pending_reapply`。待重新应用层保留原衣物、来源层和生成参数引用，但不引用旧分支的合成结果作为新结果。
- `sort_order` 表达衣物的语义层级；版本父子关系表达实际生成顺序，两者不得混为同一字段。
- 生成完成不自动修改会话。只有用户选定成功候选后，系统才创建新版本并更新当前主线。
- 修改中间层时，新分支从该层之前的版本开始。后续层复制为待重新应用配置，不携带旧的已生成图片。
- 切换分体路线与连衣裙路线时，新分支从原始人物图开始，移除互斥层，并把兼容的外套复制为 `pending_reapply` 配置。系统不自动重新生成外套；只有用户明确重新应用时才创建任务。
- 重新应用创建新任务时优先预填原 Provider 和参数。原配置不可用或不兼容时，用户必须明确选择新的兼容 Provider；系统记录变更并禁止静默回退到默认 Provider。没有兼容 Provider 时不创建任务，待重新应用配置继续保留。
- 分支或会话存在 `queued`、`waiting_provider`、`preparing`、`running` 或 `needs_attention` 任务时不得删除。用户必须先取消任务，或将需人工处理的任务明确结束。
- 当前主线分支不得直接删除。存在其他分支时，用户必须先将另一分支设为当前主线；只有一个分支时，通过删除整个会话完成，并仍须满足没有未结束任务的条件。
- 普通精准换装不创建 `OutfitSession`，继续按原任务模型运行。

为复用现有执行链，`TryOnJob` 增加以下可选字段：

- `outfit_session_id`
- `source_revision_id`
- `base_image_asset_id`
- `target_layer_role`
- `outfit_operation`：`add`、`replace` 或 `reapply`

这些字段为空时，任务语义与 V1 完全一致。分层任务失败、取消或进入 `needs_attention` 时，当前确认版本保持不变。

### 5.5 层级类型定义

层级类型由系统或管理员发布的版本化定义维护，不由普通用户直接创建。定义至少包含：

- 稳定 `key`、显示名称和定义版本。
- 身体区域、默认层级顺序和推荐遮罩策略。
- 可共存类型、互斥类型和路线约束。
- 所需 Provider 能力。

`GarmentAsset.category` 继续描述衣物本身的粗分类，例如 `upper_body`、`lower_body` 或 `dress`；`OutfitLayer.layer_role` 描述这件衣物在当前穿搭中的用途，例如 `inner_top` 或 `outerwear`。系统可以根据衣物元数据推荐角色，但创建层时必须保存用户确认后的角色，不能永久把一件上衣绑定为唯一层级。

新增马甲、围巾、鞋子等类型时，通过增加或升级 `LayerTypeDefinition` 完成，不修改 `OutfitLayer` 表结构。未来允许用户创建自定义名称时，该名称仍必须映射到一个系统身体区域和生成策略；完全无语义的任意类型不进入生成流程。

## 6. 统一生成 Provider

Provider 接口至少包含：

- `healthCheck()`
- `getCapabilities()`
- `submit(jobItem)`
- `getStatus(executionId)`
- `cancel(executionId)`
- `fetchOutputs(executionId)`

统一输入包含人物图、衣物图及类别、衣物来源、可选遮罩、模式、候选数、随机种子、可选高级参数和未来的人物参考集。V1.1 分层任务额外传入当前确认图片、原始人物参考图、目标层级类型和已确认穿搭清单；Provider 不得只根据前端显示状态推断这些输入。

能力清单至少包含：

- 支持的衣物类别。
- 是否支持手动遮罩。
- 是否支持一次生成多个候选。
- 是否支持人物多图参考。
- 是否支持批量输入。
- 是否支持中断运行中的任务。
- 支持的输入尺寸、格式和输出限制。
- 是否支持顺序分层生成 `sequential_layering`。
- 支持的层级类型 `supported_layer_roles`。
- 是否具备保持已确认衣物的能力 `preserve_existing_garments`。
- 是否接收完整穿搭上下文 `outfit_context`。
- 是否支持目标区域遮罩 `region_mask`。

能力不是每次任务由用户配置。大模型能力由适配器定义并结合当前模型配置计算；ComfyUI 能力属于工作流版本，在上传和验证时声明一次。Android 获取能力后自动调整界面。

不声明 `sequential_layering` 或不支持目标层级类型的 Provider 不得用于分层穿搭。每一步生成后执行非阻断式质量检查，检查人物、姿势、背景、已有衣物和新增衣物区域是否明显漂移。异常结果显示风险提示，但允许用户自行接受；质量检查不得在没有明确产品规则时擅自删除结果。

### 6.1 大模型 Provider

首版保存一个活动的大模型连接，包括适配器类型、API 地址、加密后的 API Key、模型名称、超时和供应商参数。更换同协议模型只修改配置；不同协议通过新增适配器支持。

适配器负责把厂商状态、错误和输出映射到统一模型。图片编辑 API 不假定完全兼容 OpenAI 风格协议。

### 6.2 ComfyUI Provider

ComfyUI 作为远程计算节点。Provider 负责输入上传、工作流填充、队列提交、状态跟踪、取消尝试、输出下载和临时文件清理。

原生 ComfyUI 服务不得无保护暴露给普通公网。连接应使用带认证的反向代理或私有通道，并限制为固定业务服务器访问。

## 7. ComfyUI 工作流版本与绑定

每个工作流版本由两部分构成：

1. 从 ComfyUI 导出的 API 格式 JSON，创建后不可原地覆盖。
2. 工作流清单，声明用途、能力、节点绑定和输出。

示例：

```yaml
schema_version: 1
workflow_id: precise-vton
version: 2
mode: precise_try_on
capabilities:
  garment_categories: [upper_body, lower_body, dress]
  manual_mask: true
  multiple_candidates: true
  multi_person_reference: false
  batch_input: false
  interrupt_running: true
bindings:
  person_image:
    node_id: "14"
    input: image
  garment_image:
    node_id: "15"
    input: image
  mask_image:
    node_id: "31"
    input: image
    optional: true
  seed:
    node_id: "35"
    input: seed
  candidate_count:
    strategy: repeat_workflow
outputs:
  - node_id: "20"
    field: images
```

上传时系统验证：

- 所有绑定节点存在。
- 输入字段存在且类型可接受。
- 至少配置一个图片输出。
- 必填能力与绑定不矛盾。例如声明支持遮罩时必须存在遮罩绑定或明确的自动遮罩节点策略。
- 工作流能在测试素材上完成最小试运行。

工作流只有 `draft`、`validated`、`active`、`retired` 状态。一次只能有一个适用于同一模式的默认活动版本；旧版本允许回滚。历史任务始终记录实际版本。

## 8. 多图与多角度演进

普通批量生成和多角度联合生成是不同能力：

- 普通批量：多张人物目标图分别执行换装，可独立成功或失败。
- 多图身份参考：每个目标图生成时附加同一人物的参考集，提高身份一致性，但不保证衣物跨视角一致。
- 跨视角联合生成：模型共同处理多个角度并约束衣物纹理、版型和身份一致性，需要专用多视角 VTON 模型。

未来人物参考集作为独立实体加入，目标照片与参考照片分开表达。Provider 使用 `multi_person_reference` 和 `joint_multiview` 等能力标识区分支持程度。ComfyUI 只是工作流编排器，不能在底层模型不支持时宣称多视角一致性。

## 9. 数据模型

建议的主要实体：

- `Asset`：逻辑素材记录，包含所有者范围、文件类型、内容哈希、尺寸、服务端输入副本状态、生命周期和创建时间；服务端图片二进制被清理后记录及历史引用仍保留。
- `PersonAsset`：人物素材、质量检测及未来的参考集关系。
- `GarmentAsset`：衣物类别、来源类型、自动分类置信度和实验标记。
- `ProviderConfig`：Provider 类型、连接参数、加密密钥、启用状态和能力快照。
- `ComfyNodeConfig`：节点地址、认证信息、健康状态和最后检查时间。
- `WorkflowVersion`：不可变 JSON、清单、校验结果和状态。
- `TryOnJob`：输入、模式、后端选择、锁定的 Provider 配置版本与工作流版本、参数、整体状态和时间。
- `JobItem`：候选执行单元、尝试次数、外部执行 ID、错误和状态。
- `GeneratedOutput`：结果素材、种子、实际参数、收藏状态和来源子任务。
- `OutfitSession`：原始人物、当前主版本、锁定的层级定义集合版本、会话名称、收藏状态和时间。
- `OutfitRevision`：父版本、生成基底、选中输出、来源任务和分支元数据。
- `OutfitLayer`：衣物素材、层级类型及定义版本、排序、应用状态、来源层、应用任务及遮罩/参数引用。
- `LayerTypeDefinition`：版本化的身体区域、层级顺序、兼容关系、冲突关系和 Provider 能力要求。

数据库首版可使用 SQLite。访问应通过仓储层，避免业务代码依赖 SQLite 特性，以便并发增长后迁移 PostgreSQL。

Android 另行保存本机素材记录及完整私有文件，并以“服务器实例标识 + 所有者范围 + 本机素材标识”作为同步边界。V1 只有一个隐式所有者范围；该边界为未来账号隔离预留，不代表当前已实现账号、切换账号或跨设备同步。

## 10. 文件存储与保留

服务端所有文件通过 `FileStorage` 接口访问：

- 首版实现为固定服务器的私有磁盘目录。
- 后续可切换 S3、OSS 或其他对象存储。
- 使用内容哈希去重。
- 图片不放入公开静态目录；下载须经过令牌认证或短时签名 URL。
- 上传时去除 GPS 等不必要 EXIF 信息，同时根据方向信息正确旋转图像。

保留策略：

- 本机人物和衣物原图持续保留，直到用户在满足引用保护规则后主动删除、卸载 App 或清除 App 数据。收藏的生成结果按现有长期保留规则处理。
- 工作流、任务参数和错误记录长期保留。
- 未收藏结果、中间遮罩和预处理文件按管理配置到期清理。
- 服务端把人物和衣物的逻辑素材记录与输入图片二进制分开管理。删除或自动清理输入图片二进制后，逻辑素材 ID、任务参数、状态、错误和谱系继续保留，并以“服务端副本不可用”表示缺失图片。
- 被 `queued`、`waiting_provider`、`preparing`、`running` 或 `needs_attention` 任务引用的服务端输入图片二进制不得删除或自动清理。
- 最后一个引用任务进入终态后，服务端输入图片二进制进入固定 24 小时宽限期；宽限期内出现新的活动引用时取消计时，并在最后活动引用再次终止后重新计时。到期只清理输入图片二进制，不清理生成结果、任务元数据、谱系或逻辑素材记录。
- 同一设备再次使用已被清理的逻辑素材时，Android 从仍存在的本机原图重新上传并恢复可用副本，不创建重复的逻辑素材条目。若本机原图也不存在，则显示不可用并要求更换素材。
- 删除无引用的本机素材只影响设备副本；仍被草稿或穿搭引用时按引用保护规则阻止删除。后端输入副本不会因本机删除而被静默立即删除，而是继续遵守活动引用和 24 小时宽限规则。
- 删除某个生成结果不删除整个任务，也不影响同一任务的其他候选结果。收藏状态不阻止用户主动删除，但删除收藏结果需要明确确认。
- AutoDL 仅保留推理期间的临时副本，完成、失败或取消后清理。
- 删除穿搭会话或分支前必须明确提示其版本数量和结果影响。删除分支不得连带删除其他分支仍引用的素材。
- 穿搭会话或分支存在未结束任务时阻止删除，并说明需先取消或结束任务。删除当前主线分支前必须先选择另一分支作为主线；只有一个分支时只能删除整个会话。
- 穿搭版本元数据和任务谱系按任务历史规则保留。只要穿搭会话或分支未被删除，其继续生成、回退、修改中间层或重新应用所必需的本机原始人物和衣物素材不得删除；服务端逻辑素材记录及确认版本图片仍受引用保护。人物和衣物的服务端输入二进制可按上述 24 小时规则清理，并在下次执行前由 Android 本机原图恢复。
- 删除穿搭分支或会话、移除待重新应用配置，或以其他方式解除最后一个穿搭引用后，相关确认版本图片才重新进入普通收藏与保留期限规则，本机人物和衣物也重新允许主动删除。
- 本机人物或衣物素材以及对应逻辑素材记录被任何未删除的穿搭会话、分支、确认版本或待重新应用配置引用时，不允许直接删除。系统必须列出受影响的引用；用户需先删除相关会话或分支，或移除待重新应用引用，才能删除素材。不得通过删除素材级联删除穿搭分支。此保护不阻止服务端输入图片二进制按 24 小时规则清理和按需恢复。
- 待重新应用的衣物配置只是对已有素材和参数的引用，不创建额外图片，也不触发生成费用。

除人物和衣物服务端输入副本固定使用上述 24 小时宽限期外，其他文件的具体保留天数不硬编码，由 Web 管理页配置。

## 11. 认证、安全与令牌初始化

系统没有账号密码体系。首次部署时运行初始化命令，生成两个高熵随机令牌：

- App Token：Android 使用，只允许素材、任务、结果和普通设置接口。
- Admin Token：Web 管理页使用，允许 Provider、密钥、工作流、清理和诊断操作。

V1 的 App Token 对应一个隐式所有者范围。所有逻辑素材、服务端输入副本和 Android 本机记录都必须落在该范围内；未来增加账号时改为显式所有者，并强制查询、迁移和下载仅返回当前所有者上传的素材。V1 不实现账号注册、账号切换或跨账号共享，但数据访问不得依赖“所有素材天然属于所有人”的假设。

令牌只在创建时显示完整值。数据库只保存慢哈希及令牌标识。管理员可在 Web 管理页轮换 App Token；Admin Token 丢失时通过服务器 SSH 执行重置命令。

其他安全要求：

- 公网通信必须使用 HTTPS。
- API Key 和 ComfyUI 凭据使用服务端主密钥加密保存。
- Admin 登录成功后使用安全、HttpOnly、SameSite Cookie 会话，避免在浏览器地址或本地存储中反复暴露令牌。
- App Token 不能调用管理接口。
- 登录尝试、连接测试和配置修改采用合理的频率限制。
- 管理操作记录时间、类型和结果，不记录密钥原文。
- IP 白名单或 VPN 是可选增强，不默认启用。
- 日志不得包含令牌、API Key、完整请求正文或原始图片。

## 12. 配置分层

### 12.1 部署级配置

通过环境变量或 `.env` 提供：数据库位置、文件根目录、服务端加密主密钥、监听地址、日志级别和初始化状态。此类配置修改频率低，通常需要重启。

### 12.2 运行时配置

保存在数据库中并通过 Web 管理页维护：ComfyUI 地址和认证、大模型连接、默认后端、超时、重试、保留期限和活动工作流。修改后无需重启。

### 12.3 工作流文件

API 格式 JSON 和清单保存在固定服务器的受控目录或 FileStorage 中，数据库保存版本、校验状态和活动指针。

## 13. Web 管理页

首版页面：

- 系统状态：业务服务、数据库、存储和 ComfyUI 连通性。
- ComfyUI 节点：地址、认证、启用状态和连接测试。
- 工作流：上传、绑定、验证、试运行、启用、停用和回滚。
- 大模型：适配器、API 地址、API Key、模型、超时和连接测试。
- 默认后端。
- 任务诊断：队列、失败原因、取消和手动重试。
- 存储：保留期限、空间占用和手动清理。
- 令牌：重新生成 App Token；敏感值只显示一次。

敏感字段只允许覆盖更新，页面不回显完整原值。

## 14. 运维手册：配置新的大模型后端

### 14.1 前置条件

- 已有与目标厂商协议匹配的适配器。
- 已取得 API 地址、密钥、模型名称和图片编辑接口限制。
- 已准备不含敏感内容的测试人物图和衣物图。

### 14.2 配置步骤

1. 使用 Admin Token 登录 Web 管理页。
2. 打开“大模型”并选择适配器类型。
3. 填写显示名称、API 地址、API Key、模型名称、请求超时和厂商专属参数。
4. 管理页从适配器显示计算后的能力清单；能力不是普通任务的逐次选项。
5. 点击“测试连接”。服务端执行不产生图片或成本最低的可用检查。
6. 点击“最小生成测试”，选择测试人物和衣物；页面在提交前提示可能产生的费用。
7. 检查输出、耗时、错误映射及取消能力。
8. 保存为 `inactive`。配置保存时 API Key 加密，页面随后只显示掩码值。
9. 手动启用配置。启用不会自动改写历史任务。
10. 如需设为全局默认，在“默认后端”中明确选择；不得在保存连接时隐式切换默认值。

### 14.3 更换模型

- 同一适配器协议下可复制现有配置并修改模型名。
- 新配置必须重新运行能力检查和最小生成测试。
- 测试通过后再启用；旧配置保持可回滚，直至确认无需保留。

### 14.4 新增协议

当目标厂商的图片编辑协议与现有适配器不同，需要开发新的 Provider Adapter。适配器必须实现统一接口、错误映射、能力计算、输出下载、超时和取消语义，并通过 Provider 契约测试后才可出现在管理页。

## 15. 运维手册：配置新的 ComfyUI 节点和工作流

### 15.1 更换 AutoDL 节点

1. 在新 AutoDL 实例部署并启动 ComfyUI、模型和自定义节点。
2. 通过认证反向代理或私有通道提供业务服务器可访问的地址。
3. 在 Web 管理页打开“ComfyUI 节点”。
4. 填写地址、认证信息和超时，保持节点为未启用。
5. 执行连接测试，并检查目标节点类型与模型是否可用。
6. 使用当前活动工作流执行最小试运行。
7. 成功后启用新节点。等待中的任务在下一次调度时使用它，但仍执行任务创建时锁定的工作流版本；新节点必须先通过该版本的兼容性检查。
8. 确认没有在途任务依赖旧实例后再关闭旧节点。

### 15.2 新增工作流

1. 在 ComfyUI 中完成调试，确保人工执行能输出目标图片。
2. 将工作流导出为 API 格式 JSON，而不是仅供画布恢复的 UI 格式。
3. 在管理页选择“上传工作流”，指定稳定的 `workflow_id`、新版本号和用途模式。
4. 上传 JSON。系统读取节点和输入字段，禁止覆盖已有版本。
5. 在绑定向导中依次指定：
   - 人物图片节点及输入字段。
   - 衣物图片节点及输入字段。
   - 可选遮罩节点及输入字段。
   - 随机种子字段。
   - 候选数量策略：工作流内部批次或重复执行。
   - 最终图片输出节点及字段。
   - 未来需要时的人物参考集绑定。
6. 声明支持的衣物类别、遮罩、多候选、多图参考、批量输入和运行中断能力。
7. 系统执行结构校验，报告不存在的节点、错误字段、缺失输出和能力/绑定矛盾。
8. 选择测试素材执行最小试运行。验证输出数量、图片格式、取消行为和临时文件清理。
9. 试运行成功后将版本标记为 `validated`。
10. 手动设为 `active`。系统记录切换时间，旧活动版本转为 `retired` 但不删除。

### 15.3 回滚

1. 在工作流版本列表选择一个曾验证成功的版本。
2. 运行快速健康检查，确认当前 AutoDL 仍具备其模型和节点。
3. 将其设为活动版本。
4. 新任务使用回滚版本；已经开始的任务继续使用创建时锁定的版本，不被中途替换。

### 15.4 能力判定准则

- `manual_mask`：存在明确遮罩绑定或已验证的等价输入。
- `multiple_candidates`：工作流支持批次，或 Provider 能安全地以不同种子重复执行。
- `multi_person_reference`：工作流存在参考集绑定，且底层模型明确支持多图身份条件。
- `batch_input`：一次执行能处理多张不同目标人物图；重复提交多个单图任务不能声明为此能力。
- `interrupt_running`：节点和调用链能中止当前执行，而不只是忽略最终输出。

管理页允许管理员声明这些能力，但必须通过结构校验和试运行尽可能验证。无法自动证明的能力显示“人工声明”标记。

## 16. 错误处理

- 素材问题：给出可理解的风险提示，并允许更换、继续或修正遮罩。
- 临时故障：自动退避重试并显示下一次尝试时间。
- Provider 离线：进入 `waiting_provider`，不计为失败。
- 配置故障：停止自动重试，在管理页突出显示诊断信息。
- 部分成功：保留成功输出，只重试失败子任务。
- 存储不足：拒绝新的素材上传和任务创建，给出可理解的空间不足说明；已经持久化但尚未执行的任务保持 `queued`，记录并展示“等待释放存储空间”的阻塞原因，不标记为失败。系统停止领取这些任务并通知管理员清理，空间恢复后自动继续调度。
- 本机素材同步失败：保留本机原图和草稿，标记为未同步并允许重试；后端不可用或令牌失效时不创建任务。
- 旧素材迁移空间不足：暂停迁移，保留未确认项的服务端原图，并提示释放空间或按受保护删除规则逐项处理。
- 迟到结果：取消后返回的结果不进入用户历史，并立即清理。

错误消息同时保存机器可判定的错误码和面向用户的中文说明。外部服务原始错误仅进入脱敏诊断记录。

## 17. 测试策略

### 17.1 Android

- 单元测试：状态映射、能力控制、表单校验和本地连接配置。
- UI 测试：首次配置、本机素材导入与离线选择、草稿恢复、按需上传、任务提交、取消、遮罩修正、收藏和下载。
- V1.1 单元/UI 测试：候选确认、另存分支、层级冲突、替换中间层、待重新应用和主线切换。
- 网络恢复测试：App 重启、切换网络及请求重复提交。

### 17.2 后端

- 单元测试：令牌权限、保留策略、任务拆分、状态机、重试和取消。
- V1.1 单元测试：不可变版本、分支创建、层级定义校验、路线互斥、任务与版本提交边界。
- Provider 契约测试：模拟大模型和 ComfyUI 均满足统一返回与错误语义。
- 数据迁移测试：SQLite schema 升级、历史任务兼容、旧服务端素材下载确认与中断续传。
- 清理测试：活动引用和未确认迁移素材不被误删，24 小时宽限重置正确，输入二进制清理后逻辑记录与历史仍存在。

### 17.3 集成与端到端

- 工作流绑定和试运行验证。
- Android → 固定后端 → AutoDL → 固定存储的完整链路。
- AutoDL 离线、运行中断线、后端重启、重复提交、API 限流和磁盘不足。
- 未授权文件下载、App Token 调用管理接口、日志敏感字段泄漏。

## 18. 验收场景

首版至少通过以下人工验收：

1. 上传一张半身人物照和一张上衣商品图，使用大模型生成并保存结果。
2. 使用同一素材切换到 ComfyUI 生成，任务记录显示正确 Provider 和工作流版本。
3. AutoDL 关闭时提交任务，任务进入等待；取消后即使节点恢复也不执行。
4. AutoDL 关闭时提交另一任务，恢复节点后自动继续并返回结果。
5. 生成两个候选，其中一个失败时保留成功结果并单独重试失败项。
6. 修正自动遮罩后重新生成，原任务和新任务关系可追踪。
7. 上传他人穿着图作为衣物来源，看到实验性提示并可继续。
8. 管理员更换 ComfyUI 地址，无需重启业务服务或更新 Android。
9. 上传并验证新工作流，启用后新任务使用新版本，旧历史仍指向原版本。
10. App Token 无法打开管理接口；轮换后旧 App Token 立即失效。
11. 素材上传失败或 App 中断后，重新进入时仍保留本地选择，可重试或取消；取消后服务端不保留未完成临时文件。
12. 服务重启后无法确认外部运行状态的任务进入 `needs_attention`，不会自动重复生成；人工选择重试后产生可追踪的新子任务。
13. 任务等待期间切换默认模型或活动工作流，原任务仍使用创建时锁定的配置版本；锁定版本不可用时进入 `needs_attention`。
14. 部分失败任务按原参数重试时，在原主任务下生成新的可追踪子任务并保留旧失败记录；修正遮罩后则生成关联的新主任务。
15. 活跃任务引用的素材无法直接删除；终态任务的图片确认删除后，历史仍显示不含图片的记录和删除占位状态。
16. App Token 失效后，Android 保留服务器地址并要求重新认证；服务端任务继续执行，输入新令牌后可同步最新状态。
17. 等待中的 ComfyUI 任务可以迁移到新的物理节点，但必须继续使用创建时锁定的工作流版本，并在新节点通过兼容性检查后才执行。
18. 存储不足时拒绝新上传和新任务；已入队任务保持带阻塞原因的 `queued`，清理空间后自动继续。
19. ComfyUI 临时离线时允许任务进入 `waiting_provider`；缺少活动配置、能力不兼容或配置校验失败时阻止提交且不创建任务。
20. 生成多个候选时可单独取消一个候选而不影响其他候选；取消整个任务后，已有成功结果则汇总为部分成功，没有成功结果则为已取消。
21. 原 Provider 不支持手动遮罩时，可使用兼容且支持遮罩的其他 Provider 创建关联修正任务；验收环境至少存在一个可用的手动遮罩 Provider。
22. `waiting_provider` 任务不自动过期，节点恢复后继续执行，用户也可随时取消。
23. V1.1 从人物图依次生成内搭、外套和下装，并保留每一步确认版本。
24. 每层生成多个候选时，选择一个继续，并可把其他候选另存为独立分支。
25. 替换内搭后，原外套和下装进入待重新应用，不自动创建任务或产生费用。
26. 对待重新应用的衣物可选择重新使用原素材、更换衣物或移除；重新应用产生新的可追踪任务。
27. 连衣裙与内搭、下装互斥但可搭配外套；切换路线时创建新分支并保留原分支。
28. 分层任务失败、取消或进入 `needs_attention` 时，当前确认版本不变。
29. 不支持 `sequential_layering` 或目标层级的 Provider 不可选择，并显示能力不足原因。
30. 普通单件精准换装任务和既有历史数据不受分层穿搭字段影响。
31. 旧分支及其任务、错误、Provider/工作流版本和费用相关记录可追踪。
32. 系统新增层级类型时无需修改 `OutfitLayer` 数据表结构，旧会话继续按其层级定义版本解释。
33. 未删除穿搭会话和分支所需的原始人物、确认版本图片及待重新应用衣物不因普通保留期限而清理；解除最后引用后才恢复普通清理规则。
34. 删除被穿搭版本或待重新应用配置引用的人物或衣物时，系统阻止删除并列出引用；移除相关引用后才允许删除，且不得级联删除分支。
35. 分体路线与连衣裙路线互相切换时，新分支移除互斥层、保留外套为待重新应用，且不自动生成或收费；原分支继续完整保留。
36. 待重新应用衣物的原 Provider 不可用时，系统要求用户明确选择新的兼容 Provider，显示配置变化并记录实际版本；没有兼容 Provider 时不创建任务且保留待重新应用状态。
37. 有未结束任务的穿搭分支或会话无法删除；当前主线必须先切换到其他分支才能删除，只有一个分支时通过删除整个会话完成。
38. 后端离线时仍可导入、浏览、筛选和选择本机人物与衣物，并保存草稿；点击生成时保留草稿并提示连接后端。
39. 后端恢复后，未同步的选中素材自动从 Android 私有副本上传，检测与配置校验通过后再创建任务；上传中断不要求重新进入相册。
40. 最后活动任务终止 24 小时后只清理人物和衣物的服务端输入二进制；任务、结果、谱系和逻辑素材记录仍存在，同设备再次使用时可从本机原图恢复副本。
41. 新活动引用出现在宽限期内时取消清理；`queued`、`waiting_provider`、`preparing`、`running` 或 `needs_attention` 引用期间绝不清理输入二进制。
42. 升级后的首次认证连接只迁移当前所有者范围内的旧服务端素材；文件完整落盘确认前不启动清理，迁移中断、空间不足或认证改变时可安全停止和恢复。
43. 删除无引用本机素材不删除历史或服务端记录；被草稿或保留中的穿搭流程引用时先阻止并列出需解除的引用。
